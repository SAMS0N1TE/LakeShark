# T-Display-P4 SDK migration

T-Display-P4 profiles use the isolated patched SDK at
`C:\esp\v5.5.4\esp-idf`, branch `lakeshark-v5.5.4`. Other profiles retain
the patched 5.4.3 SDK. The stock Espressif 5.5.4 installation is not modified.
Dot-source `bench/idfenv.ps1 -Config t-display-p4` to select the 5.5 Python
environment and tools. Register this SDK's tools for `esp32p4` with IDF's
tool installer before exporting on a new machine.

The USB freed-node and descriptor-error patches are carried from the release
SDK. The SDMMC patch is ported to 5.5.4's internal DMA allocator: on allocation
failure, PSRAM-DMA-capable SoCs retry with a cache-aligned, padded PSRAM buffer.
The legacy board DMA-info callback is retained only for older SDKs: 5.5.4 no
longer consults it for sector bounce allocation. Its buffers therefore prefer
internal DMA memory and use the patched PSRAM fallback under memory pressure.
The USB and SDMMC patches are supplied for the unmodified 5.5.4 base and checked by
`bench/patch-idf.ps1`. The P4 reset fix is upstream: `system_internal.c:70`
resets MSPI before AHB DMA (`:77`), H264 (`:86`), and SDMMC (`:103`).

## Cache serialization review

In the 5.5.4 SDK, `esp_cache_msync.c:30` defines one shared spinlock.
The public internal lock helpers (`:35`, `:40`) use the safe OS critical-section
API. Writeback is guarded both in chunks (`:54`) and in ISR context (`:65`);
invalidation is guarded at `:133` and `:148`. The chunking mutex is acquired
only when `xPortCanYield()` (`:79`), so ISR/critical callers do not block on it.
`flash_mmap.c:319` and `esp_mmu_map.c:407` take the same spinlock around their
address-range invalidations. Boot/image-loading cache operations run during
startup; PSRAM XIP is disabled for this profile.

The older LakeShark HAL wrappers would still intercept external HAL calls if
their linker flags were enabled. They add a distinct inner spinlock, rather
than recursively acquiring IDF's lock; no inverse ordering was found in the
reviewed paths. They are redundant for the concurrent runtime paths in 5.5.4.
Both wrapper definitions and their linker flags are therefore disabled for
5.5.4 and later, while the older SDK workaround is retained. Future SDK upgrades
must recheck these paths. A successful build does not prove the historical ROM
spin is resolved on hardware.

## First boot constraints

The profile targets P4 revision 0.1 through 1.99, 16 MB flash, and an ESP32-C6
hosted slave. ESP-Hosted remains pinned to 2.12.9 and Wi-Fi Remote to 0.16.3;
the installed slave firmware version was not queried or changed. The release
dependency lock can be copied locally with its IDF version changed to 5.5.4;
it remains ignored by git.

The partition layout is unchanged: NVS at 0x9000, OTA slots of 0x480000 bytes
at 0x10000/0x490000, storage at 0x910000, and otadata at 0xd20000. Persistent
settings, rollback behavior, USB unplug recovery, SD memory-pressure fallback,
cache concurrency, and hardware audio still require first-boot/soak validation.
No hardware execution is part of this migration.

## SPI DMA memory-pressure recovery

`esp-idf-v5.5.4-spi-dma-cleanup.patch` is required by `patch-idf.ps1`.
Compared with upstream [release/v5.5](https://github.com/espressif/esp-idf/blob/release/v5.5/components/esp_driver_spi/src/gpspi/spi_master.c)
and [master](https://github.com/espressif/esp-idf/blob/master/components/esp_driver_spi/src/gpspi/spi_master.c),
it carries the NULL RX cleanup guard and the release branch's internal-DMA
length-alignment/copy-length correction. The local addition publishes buffer
ownership before allocation and frees partial allocations without copying an
unreceived reply. Upstream release/v5.5 still publishes only after both setup
calls, which can leak an allocated TX buffer if RX setup fails.

The host gate compiles the real SDK functions with injected TX/RX allocation
and cache-sync failures (`tests/test_idf_spi_dma.py`). It checks error returns,
no outstanding allocations, unchanged replies on error, no TX padding overread,
and allocation-free inline three-byte transfers. Run it directly with:
`python bench/tests/test_idf_spi_dma.py --idf C:/esp/v5.5.4/esp-idf`.
The radio protocol suites exercise inline and persistent frames through the
same production transport and verify failure propagation.

P4 memory policy retains flash-off-safe ISR, DSI object, system, logging,
libc lock and flash-driver placement. The new IRAM symbol names alone are not
regressions: 5.4.3 linker fragments already kept most of these paths in RAM.
FreeRTOS task-only APIs use its documented flash-placement option; ISR and
context-switch paths stay internal. Wi-Fi is on the C6, so the proxy's sleep
IRAM optimization is disabled along with PM's selected sleep optimization.
NimBLE's new dynamically allocated host pools use supported external allocation
while its memory optimizations stay enabled; controller/HCI DMA transport is
separate and unchanged. DSI cache safety selects internal objects in 5.5.4 and
must remain enabled for uninterrupted scanout during flash writes.

No build or host test establishes boot heap values. Repeat the SX1262 boot with
USB and audio active and require internal free >= 26103, DMA free >= 9723,
largest DMA block >= 8704 bytes. Verify sustained RSSI polling under memory
pressure, BLE/C6 operation, OTA/NVS writes with scanout, and hardware audio at
the user's selected volume before claiming the runtime target is met.

### Size audit rationale

The reference is 2.9.0 and the migrated app is 2.9.1; archive deltas include
application changes as well as the SDK migration.

The supplied 2.9.0/5.4.3 map uses 363966 bytes of static D/IRAM; the initial
2.9.1/5.5.4 map uses 364914 (+948). IRAM is 106338 -> 110154 (+3816),
DRAM data 71524 -> 72976 (+1452), and DRAM BSS 186104 -> 181784 (-4320).
This small net static increase cannot explain the entire measured 9584-byte
boot-heap loss. `libbt.a` static RAM fell 6166 -> 494 bytes while 5.5 enables
`BT_NIMBLE_STATIC_TO_DYNAMIC`; its internal-only allocation choice moves those
pools into the runtime DMA heap. External host allocation addresses that
migration while retaining NimBLE's supported memory optimizations.

IRAM archive changes include hardware support 17432 -> 19176 (+1744), SPI
4924 -> 5856 (+932), and newlib 2660 -> 3580 (+920). Keep the hardware/interrupt
helpers, libc locks/abort/atomics, SPI ISR and flash operations internal:
5.4.3 linker fragments already mark these cache-off paths `noflash`, and their
new Kconfig labels are not permission to put them in flash. FreeRTOS itself
is 22010 -> 21964 IRAM before optimization; `FREERTOS_IN_IRAM` is hidden and
always enabled, so use the supported task-only placement option instead.
Logging and timer IRAM are effectively unchanged (568 -> 594; 1242 -> 1242).
LCD IRAM is 200 -> 204; its internal object allocation is required by the
cache-safe DSI selection. RMT is 3602 -> 3508 IRAM: 5.4.3 already annotated its ISR/encoder code
for RAM, so retain the equivalent 5.5 placement. Unused analog-comparator,
MCPWM and PARLIO defaults have no linked archive contribution in this
application and are left alone.

Keep `FREERTOS_PLACE_FUNCTIONS_INTO_FLASH=y`. The RISC-V patch retains
`pxPortGetCoprocArea`, `pxPortUpdateCoprocOwner`, `vPortTaskPinToCore`, and
`xPortCheckValidTCBMem` in IRAM. The first three are reached by interrupt entry
and HWLP/PIE/FPU save/restore; the fourth is called by internal
`vTaskGetSnapshot`. The stack-pointer helper and ownership exchange are inline;
coprocessor size/alignment arrays compile to immediate values on the stack,
owner tables are DRAM, and assertion/exception targets are internal. Two
coprocessor panic strings are explicitly DRAM, including the already-IRAM
`vPortCoprocUsedInISR` message. Coprocessor save areas on PSRAM task stacks
remain external; flash-writing tasks must still have DRAM stacks.

Current ELF sizes of the four newly retained helpers are 188 + 82 + 4 + 58 =
**332 IRAM bytes**. This is an estimate from existing linked code, not a
patched-link measurement; relaxation/alignment can change it. The panic
strings add 104 raw DRAM bytes; the DSI ISR tag adds 8 raw DRAM bytes through
`DRAM_STR("lcd.dsi")`. Aligned costs require a rebuild after applying patches.

REC manual/automatic SPIFFS saves use a transient 8192-byte `ls_flash_task`
DRAM stack for the complete save (probe, writes, close, rename, sidecar).
Allocation failure fails the save without writing from PSRAM. SD retains its
external-stack worker. No permanent REC stack is added; each SPIFFS save needs
8192 bytes plus a TCB and allocator overhead temporarily. LoRa now keeps a
40-byte DRAM descriptor/inline storage under the radio lock through copyback.

`build_tdp4/ccache`, and `bench/build.ps1 t-display-p4`. Binary: `0x3eaeb0`
