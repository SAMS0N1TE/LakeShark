# TILES

Reach it from **HOME > FIELD > TILES**, immediately after MAP. Select a region
with UP/DOWN or a tap; ENTER opens INFO. OPTIONS contains a REGION submenu with
OPEN ACTIVE MAP, SHOW REGION LOCATION, DOWNLOAD / RE-DOWNLOAD, DELETE and INFO.
BACK returns one level. The root OPTIONS also has REFRESH, RECEIVE and a globe
speed level with `<` and `>`. The PREV/NEXT line allows touch navigation through
long lists. TAB selects the bottom controls for keyboard navigation.

OPEN uses the existing CartoCore SD loader and full-grid map view. A key or tap
dismisses that view through the existing CartoCore router. SHOW REGION LOCATION
centres the ordinary MAP app on the region's bbox without installing it.

The catalog URL is `https://cartocore-maps.pages.dev/catalog.json`. Map files
are siblings of that URL. A successful refresh caches the catalog in
`/sdcard/maps/catalog.json`; offline entry merges it with SD files. A size or
SHA difference marks an installed file UPDATE AVAILABLE. Interrupted transfers
keep `.ctile.part` files, which are listed as PARTIAL. Re-download starts over;
it does not resume. Installed files are replaced only after size/header/SHA
verification. DELETE confirms before removing the installed and partial files.

## Catalog format

```json
{
  "version": 1,
  "regions": [
    {
      "name": "Central New Hampshire",
      "file": "central_nh.ctile",
      "bytes": 123456,
      "bbox": [-72.1, 43.1, -71.2, 44.2],
      "zmin": 8,
      "zmax": 16,
      "description": "Offline roads, trails and water.",
      "sha256": "64 lowercase hexadecimal characters"
    }
  ]
}
```

`bbox` is `[west, south, east, north]` in degrees. Zooms are inclusive.
`file` is a plain `.ctile` filename of at most 127 characters using ASCII
letters, digits, underscores, dots and hyphens; directory traversal is rejected.
SHA is optional (omit it or use an empty string); when present it is checked
before publication, including laptop pushes matching a known catalog filename.
The catalog is bounded to 48 regions and 64 KiB. CTILE header versions 2–6
share the metadata offsets used by the generator and current firmware reader.

```powershell
python tools/carto_catalog.py path/to/maps
python tools/carto_catalog.py path/to/maps --metadata descriptions.json -o catalog.json
```

Metadata is keyed by filename, e.g.
`{"central_nh.ctile":{"name":"Central NH","description":"Roads and trails"}}`.
The generator checks header magic/version/declared size/bbox/zooms and streams
SHA256 over each file. It does not rebuild tiles or copy any engine code.

## Receive

Connect WiFi and insert SD, then choose RECEIVE. It starts the existing one-shot
HTTP PUT server at the displayed board IP, port 8080, for five minutes:

```powershell
curl.exe --fail --upload-file central_nh.ctile "http://BOARD_IP:8080/maps/central_nh.ctile"
```

Append `?f=1` to replace an existing file. BACK opens cancellation confirmation.
The globe adopts the incoming header bbox once the first 64 bytes arrive. OPEN
after completion selects the received filename. Unknown files receive header
and length checks; full geometry validation happens in the existing OPEN reader.
The server is intended for the device's trusted local WiFi network.

`bench/out/tiles/` contains PNGs and text grids for LIST, INFO, DOWNLOAD at
0/35/80/100%, and RECEIVE in portrait and landscape, plus interaction evidence.
These are simulator fixtures, not evidence of a live network or hardware transfer.
The globe's coarse original land mask is 324 bytes, generated by
`bench/tools/tiles_world.py`; sphere projection/shading is cached by geometry.
Rotation changes an integer longitude offset at 80 ms intervals. Small regions
use a three-degree locator halo to remain visible at this coarse resolution;
the locator's glyph brightness increases with transfer progress.

No commit, public push, flashing, hardware execution, audio changes or Forge
contact was performed. CartoCore engine files were not edited. SD OPEN now uses the callback streaming reader; the embedded map stays in memory.
See `bench/CARTO_STREAMING.md` for budgets and verification. TILES chooses a display zoom
within the region's zoom range (0–22); console `zoom` retains its 13–15 range.
Live catalog availability, SD/WiFi transfer and board rendering
remain unverified without running on hardware.

remain as `<name>.ctile.pending`. Closing that source or boot recovery installs
the verified pending file. Active-map selection is retained in NVS across
reboots; a missing file falls back to the embedded Franklin mini map. The MAP
app offers CartoCore smooth and CartoCore braille alongside its libcarto fills.


## Cell sets and place search (API 2 / CTILE v7)

TILES > SEARCH (or `S`) opens the shared offline place picker. Type two or
more characters on BLE, or tap KEYBOARD for live on-screen typeahead. Results
show country/state/city and parent, ranked by the engine. MAP > GO TO > SEARCH
PLACES uses the same picker and jumps without downloading. Country/state
coverage uses stored polygon intersections; city coverage starts at 25 km and
has `<` / `>` controls in 5 km steps, up to 500 km.

Picking a TILES result shows installed/unavailable cells, download bytes
(including a missing index and overview), and SD free space. DOWNLOAD persists
a place record before starting the queue. The globe reports the current file's
progress; SEARCH > PROGRESS or OPTIONS > DOWNLOAD PROGRESS reopens it. Leaving TILES and restarting the board both preserve the queue.
INSTALLED lists up to 32 named places with UPDATE and confirmed DELETE. Each
record owns a z8 bitset; a cell is removed only when no other installed or queued
place owns it. Corrupt ownership records prevent cell deletion. INFO credits
GeoNames under CC BY 4.0; base metadata and `ATTRIBUTION.txt` contain the credit.

The SERVER button edits the base URL, default
`https://cartocore-maps.pages.dev/`. It and the last-picked country are saved
in `/sdcard/maps/cells.settings`, on the existing worker, with no new NVS calls.
Base search data remains on SD. Country shards are requested from engine hints;
at most two extra countries are loaded for a query, plus the retained picked
country. A country qualifier resolves ambiguous city names.

### Server layout

Publish the directory produced by `tools/carto_push.py --prepare`:

```text
cells/catalog.ccm             bounded binary size / SHA256 table
cells/index.cci               CartoCore API 2 binary global index
cells/overview.ctile          z0..7 overview
cells/8/<x>/<y>.ctile         independently downloadable z8-owned cells
places/places_base.ccpl
places/places_<ISO2>.ccpl
places/ATTRIBUTION.txt
```

`catalog.ccm` is little endian: 128-byte header, magic `CCMAPS1\0`, entry
count u32 at 8, index bytes u32 at 12 / SHA256 at 16, base bytes u32 at 48 /
SHA256 at 52, edition hash at 84, reserved through 127. Sorted 40-byte entries
are cell id u32, bytes u32, SHA256[32]; id 0 is the overview, otherwise
`1 + x*256 + y`. The engine index and this size table must describe the same
cell revisions. The board checks catalog hashes before opening a cell, so old
cell revisions cannot be read using new index offsets. Hosts must support
HTTP Range; a server returning 200 instead of 206 restarts that file safely.

On SD, files are flat within `/sdcard/maps/cells/`:
`index.cci`, `catalog.ccm`, `overview.ctile`, `8-<x>-<y>.ctile`.
Downloads use `.part` plus a size/hash binding in `.part.meta`, verify SHA256
and the format, and rename with `.bak` rollback/recovery. Generation changes
release decoded state; the last complete displayed frame survives replacement.
Per-place records are `/sdcard/maps/installed/<key>.ccpi`. A failed transfer
keeps its partial bytes; a hash/format failure keeps the old installed asset.

### Laptop preparation and direct upload

```powershell
python tools/carto_push.py C:/Users/DEV/CartoCore/data/cells-nh --places C:/Users/DEV/CartoCore/data/places/out/z8 --prepare bench/out/cells/server
# On the board's console, entered by the hardware operator:
# carto recv 8080 3600
python tools/carto_push.py bench/out/cells/server BOARD_IP --assets --country US --code DISPLAYED_32_HEX_CODE
# Then on the board: carto open cells ; carto show 12, or enter MAP.
```

The authenticated WiFi receiver accepts multiple asset PUTs for the session;
legacy single `.ctile` uploads keep their existing one-shot behavior. Each
asset PUT requires `X-Carto-SHA256`, the session code and the station interface.

If WiFi is unavailable, the hardware operator can explicitly choose the console
port (the tool never enumerates ports):

```powershell
python tools/carto_push.py bench/out/cells/server --assets --country US --serial-port COM_NUMBER --baud 115200
```

This uses `carto upload begin NAME SIZE SHA256`, `data OFFSET CRC32 HEX`, and
`end`. 32-byte chunks fit the existing 128-character console limit, duplicate
ACK retries are idempotent, and rerunning resumes each incomplete asset. Serial
is substantially slower than WiFi for a full region. No port was opened while
implementing or testing this path; its protocol was tested with a fake serial
endpoint and the production worker transaction functions.

### Host verification and memory

`python bench/tools/test_cells.py` runs the real worker and screens against a
`file://` server: bootstrap, live keyboard/BLE queries, shard fetch, size/radius
preview, persistent interrupted queue, restart, SHA checks, shared ownership,
MAP GO TO, cell edges and per-cell overview fallback, plus upload CRC/resume.
The PNGs are in `bench/out/cells/`. `test_carto_recv.py` separately exercises
the real HTTP handler with mocked transport and the Python sender on localhost.

All new retained service state is PSRAM: about 108 KiB on the 64-bit host,
plus about 4.6 KiB for the picker. V7 uses a 16 MiB scene arena, 4 MiB idle
scratch, 2 MiB decoded cache, 4 KiB index page, and grid-dependent PSRAM hot
planes/cells/publication. The NH mixed z8 overview/detail view peaks at about
8.68 MiB of scene arena. Legacy maps keep the previous smaller arenas. Zstd
state is arena-backed in PSRAM. The existing 32 KiB DMA read bounce is shared
by the index and all four LRU handles; no second DMA buffer or task is added.

For an existing P4 build directory, set `CONFIG_FATFS_ALLOC_PREFER_EXTRAM=y`
and `CONFIG_FATFS_FS_LOCK=24` in its sdkconfig; defaults alone do not override
previously saved values. The component configure check enforces these settings.

P4's mount capacity increases from 8 to 24 files, with the FAT table/buffers
configured to prefer PSRAM and 24 filesystem locks. New application internal
state is below 128 bytes; the eight additional FAT lock records are small.
SDK HTTP/VFS transient heap use and hardware throughput remain unmeasured.
All file work stays on the existing PSRAM carto worker (or existing receiver),
and flash/NVS remains on the pre-existing internal-stack dispatcher. The host
TUI boundary gate covers 16 entry points, with a maximum frame of 208 bytes.
